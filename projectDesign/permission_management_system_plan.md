# 권한 관리 시스템 기획서

## 1. 개요

### 1.1 목적

본 시스템은 로그인 기반의 사용자 및 권한 관리 시스템으로, 사용자
역할(Role)에 따라 시스템 메뉴 및 콘텐츠에 대한 접근/관리 권한을 제어하는
것을 목적으로 한다.

시스템은 다음 3종류의 사용자 역할을 기본으로 한다.

1.  **시스템 관리자 (System Administrator)**
2.  **관리자 (Administrator)**
3.  **일반 사용자 (User)**

시스템 관리자는 전체 시스템 구조와 관리자 권한을 관리하고, 관리자는
시스템 관리자가 허용한 범위 내에서 일반 사용자와 권한을 관리한다.

------------------------------------------------------------------------

## 2. 기본 설계 원칙

### 2.1 권한 관리 기본 구조

권한 구조는 다음과 같이 구성한다.

``` text
시스템 관리자
    │
    ├─ 메뉴 생성/수정/삭제
    ├─ 콘텐츠 메뉴 생성/수정/삭제
    ├─ 관리자 계정 관리
    ├─ 관리자 권한 범위 설정
    │
    ▼
관리자
    │
    ├─ 일반 사용자 관리
    ├─ 사용자별 역할/권한 설정
    ├─ 허용된 메뉴에 대한 권한 부여
    └─ 허용된 콘텐츠 관리
    │
    ▼
일반 사용자
    │
    └─ 부여받은 메뉴/콘텐츠 접근
```

### 2.2 권한 관리 방식

기본적으로 **RBAC(Role Based Access Control)** 구조를 사용한다.

다만 역할만으로 모든 권한을 결정하지 않고 필요할 경우 사용자별 추가
권한을 부여할 수 있도록 한다.

``` text
사용자
 ├─ 기본 Role
 │    ├─ SYSTEM_ADMIN
 │    ├─ ADMIN
 │    └─ USER
 │
 └─ 개별 Permission
      ├─ 메뉴 접근
      ├─ 조회
      ├─ 등록
      ├─ 수정
      ├─ 삭제
      └─ 관리
```

# 3. 사용자 역할

## 3.1 시스템 관리자

시스템 전체를 관리하는 최상위 사용자이다.

### 주요 권한

-   시스템 관리자 계정 관리
-   관리자 계정 생성/수정/비활성화
-   일반 사용자 조회
-   전체 메뉴 관리
-   콘텐츠 메뉴 관리
-   메뉴 구조 및 순서 관리
-   관리자별 관리 가능 메뉴 지정
-   관리자별 권한 범위 지정
-   전체 권한 정책 관리
-   시스템 설정
-   전체 접속 로그 조회
-   전체 권한 변경 이력 조회

### 시스템 관리자 전용 기능

``` text
시스템 관리
 ├─ 사용자 관리
 ├─ 관리자 관리
 ├─ 메뉴 관리
 ├─ 콘텐츠 관리
 ├─ 권한 관리
 ├─ 접속 로그
 ├─ 권한 변경 이력
 └─ 시스템 설정
```

------------------------------------------------------------------------

## 3.2 관리자

시스템 관리자가 지정한 범위 내에서 사용자와 권한을 관리하는 사용자이다.

### 주요 권한

-   일반 사용자 조회
-   일반 사용자 생성
-   일반 사용자 수정
-   일반 사용자 비활성화
-   사용자 권한 설정
-   허용된 메뉴에 대한 사용자 접근 권한 부여
-   허용된 콘텐츠 관리
-   자신이 관리하는 사용자의 접속/변경 이력 조회

### 제한

관리자는 다음 작업을 수행할 수 없다.

-   시스템 관리자 생성
-   시스템 관리자 권한 변경
-   자신의 관리 범위를 초과한 권한 부여
-   시스템 관리자가 허용하지 않은 메뉴 관리
-   시스템 전체 설정 변경

### 권한 위임 제한 원칙

관리자는 **자신이 가진 권한보다 높은 권한을 다른 사용자에게 부여할 수
없다.**

예:

``` text
시스템 관리자
 └─ 관리자 A
      ├─ 고객관리 : 조회/등록/수정
      └─ 통계 : 조회

관리자 A가 사용자에게 부여 가능한 최대 권한

고객관리 : 조회/등록/수정
통계     : 조회
```

관리자 A는 고객관리의 `삭제` 권한이나 시스템 설정 권한을 사용자에게
부여할 수 없다.

------------------------------------------------------------------------

## 3.3 일반 사용자

관리자로부터 부여받은 권한에 따라 시스템을 사용하는 사용자이다.

### 주요 기능

-   로그인
-   자신의 프로필 조회/수정
-   허용된 메뉴 조회
-   허용된 콘텐츠 이용
-   자신에게 부여된 기능 실행

일반 사용자는 원칙적으로 다른 사용자의 권한을 관리할 수 없다.

# 4. 로그인 및 계정 관리

## 4.1 로그인

기본 로그인 방식

``` text
아이디
비밀번호
```

향후 확장을 고려하여 다음 인증 방식도 적용 가능하도록 설계한다.

-   이메일 인증
-   OTP / MFA
-   SSO
-   Google / Microsoft 계정 연동
-   사내 인증 시스템 연동

## 4.2 계정 상태

사용자 계정은 다음 상태를 가진다.

  상태        설명
  ----------- -------------------------
  ACTIVE      정상 사용
  INACTIVE    비활성
  LOCKED      로그인 실패 등으로 잠김
  SUSPENDED   관리자에 의해 사용 중지
  DELETED     삭제 처리

실제 데이터는 감사 및 이력 추적을 위해 물리 삭제보다 **논리 삭제(Soft
Delete)** 를 기본으로 한다.

# 6. 메뉴 관리

메뉴는 시스템 관리자가 생성한다.

## 6.1 메뉴 구조

메뉴는 계층형 구조를 지원한다.

``` text
Dashboard

사용자 관리
 ├─ 사용자 목록
 ├─ 사용자 등록
 └─ 사용자 권한

콘텐츠
 ├─ 공지사항
 ├─ 자료실
 └─ 게시판

시스템 관리
 ├─ 관리자 관리
 ├─ 메뉴 관리
 ├─ 권한 관리
 └─ 로그 관리
```

## 6.2 메뉴 정보

메뉴는 다음 정보를 가진다.

  필드             설명
  ---------------- -----------------------
  Menu ID          메뉴 식별자
  Parent Menu ID   상위 메뉴
  Menu Name        메뉴명
  Menu Type        MENU / CONTENT / LINK
  Path             접근 URL
  Icon             메뉴 아이콘
  Sort Order       표시 순서
  Active           사용 여부
  Visible          메뉴 표시 여부

## 6.3 메뉴 권한

메뉴별로 다음 권한을 설정할 수 있다.

``` text
VIEW
CREATE
UPDATE
DELETE
MANAGE
```

예:

  메뉴            조회   등록   수정   삭제   관리
  ------------- ------ ------ ------ ------ ------
  사용자 관리        O      O      O      X      X
  공지사항           O      O      O      O      O
  시스템 설정        X      X      X      X      X

# 8. 권한 관리

## 8.1 권한 구성

권한은 다음 관계로 관리한다.

``` text
User
 ↓
Role
 ↓
Menu
 ↓
Permission
```

추가적으로 사용자별 예외 권한을 지원한다.

``` text
User
 ├─ Role Permission
 └─ User Permission Override
```

## 8.2 권한 우선순위

권장 우선순위는 다음과 같다.

``` text
1. 시스템 관리자 권한
2. 사용자 개별 제한(DENY)
3. 사용자 개별 허용(ALLOW)
4. Role 권한
5. 기본 DENY
```

명시적으로 허용되지 않은 기능은 접근할 수 없는 **Default Deny** 정책을
사용한다.

------------------------------------------------------------------------

# 9. 관리자 권한 범위

시스템 관리자는 관리자마다 관리 범위를 지정할 수 있다.

예:

``` text
관리자 A
 ├─ 사용자 관리
 ├─ 공지사항 관리
 └─ 자료실 관리

관리자 B
 ├─ 사용자 관리
 └─ 고객 콘텐츠 관리

관리자 C
 └─ 통계 조회
```

이를 통해 모든 관리자가 동일한 관리자 권한을 가지지 않도록 한다.

------------------------------------------------------------------------

# 10. 사용자 권한 설정 화면

관리자가 사용자를 선택하면 다음과 같은 형태로 권한을 설정한다.

``` text
사용자 : 홍길동
Role   : USER

[메뉴 권한]

                     조회  등록  수정  삭제  관리
-------------------------------------------------
Dashboard             ✓
사용자 관리           ✓
공지사항               ✓    ✓
자료실                 ✓    ✓    ✓
통계                   ✓
시스템 설정
```

관리자는 자신에게 부여된 권한 범위 안에서만 체크박스를 변경할 수 있다.

# 17. 권한 체크 흐름

사용자가 특정 기능에 접근할 때 다음 순서로 권한을 확인한다.

``` text
로그인 확인
   ↓
계정 상태 확인
   ↓
SYSTEM_ADMIN 여부
   ↓
사용자 개별 DENY 확인
   ↓
사용자 개별 ALLOW 확인
   ↓
Role 권한 확인
   ↓
메뉴 Permission 확인
   ↓
허용 / 거부
```

관리자가 다른 사용자의 권한을 변경하는 경우 추가로 다음을 확인한다.

``` text
관리자 로그인
   ↓
대상 사용자 관리 가능 여부
   ↓
관리자 ADMIN_SCOPE 확인
   ↓
요청 권한 ≤ 관리자 보유 권한 확인
   ↓
권한 변경
   ↓
AUDIT_LOG 기록
```

# 18. 보안 요구사항

필수 적용 항목:

-   비밀번호 단방향 해시 저장
-   로그인 실패 횟수 제한
-   계정 잠금
-   세션 만료
-   CSRF 방어
-   XSS 방어
-   SQL Injection 방어
-   API 서버 권한 검증
-   관리자 기능 서버 측 권한 검증
-   권한 변경 감사 로그
-   주요 관리자 작업 재인증 고려

특히 프론트엔드에서 메뉴를 숨기는 것만으로 권한을 제어해서는 안 된다.

모든 API 요청에서 서버가 실제 권한을 검증해야 한다.

# 19. 핵심 업무 규칙

1.  시스템 관리자는 전체 시스템을 관리한다.
2.  시스템 관리자만 메뉴 구조를 생성/변경할 수 있다.
3.  시스템 관리자는 관리자에게 관리 범위를 부여한다.
4.  관리자는 자신의 관리 범위 안에서 일반 사용자를 관리한다.
5.  관리자는 자신보다 높은 권한을 부여할 수 없다.
6.  일반 사용자는 다른 사용자의 권한을 관리할 수 없다.
7.  메뉴 접근 권한과 기능 권한을 분리한다.
8.  권한이 명시적으로 없는 경우 접근을 거부한다.
9.  모든 권한 변경은 Audit Log에 기록한다.
10. 삭제된 계정 및 권한 이력은 감사 목적상 추적 가능해야 한다.
